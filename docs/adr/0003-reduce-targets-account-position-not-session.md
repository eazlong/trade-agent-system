# 减仓的作用对象是「账户持仓」，不是「会话」

事件熔断的自动减仓要做两件事：算出「减多少」，以及**发生恰好一次**。这两件事都需要一个东西来指代「被减的那个对象」。最顺手的挂靠点是实盘会话——用户看得见它、事件窗口也是围绕会话展示的。我们**不**挂会话，而是挂**交易所账户的持仓**：作用面按「受影响品种」逐个账户持仓计算，幂等键是 `(交易所账户 × 事件 × 第 N 次 × 品种)`，不含会话。

理由是「持仓 ⊂ 账户」是代码里唯一为真的隶属关系，而**会话会消失**：`LiveSession.status` 有 `pending / running / paused / stopped / error` 五态，全仓**没有任何代码在会话停止时关仓**（`trading/views.py:496`、`:552` 只写 `status` 与 `stopped_at`），本地也**没有任何持仓表**——持仓只存在于交易所账户侧（`adapter.get_positions()` 实时拉）。用会话去指代一个不属于它的东西，会恰好在最需要保护的时刻失效：**用户停会话的常见原因正是觉得市况不对**，而那正是事件熔断该起作用的时候。

## Considered Options

- **减仓挂在会话上，各会话各减自己那一份。** 被否决：会话消失则敞口被完整放空；且同一账户下两个会话跑同一品种时，按会话会减两次（敞口到 25% 而非 50%）——而它们其实是**同一个持仓**。
- **减仓挂在「组合总敞口」上，全账户减半。** 被否决：会出现「某品种完全没被碰、另一个被清掉」，事后无法向用户解释，而「事后能解释减了多少」是硬要求。
- **加一张本地持仓表，以它为作用对象。** 被否决：持仓是交易所侧的事实，本地表会与它分叉，而按分叉的账面算出的「一半」在失真时可能反向开仓——即熔断动作反而加大敞口。与「减仓必须依赖交易所侧只减不增」是同一个理由。
- **以「有活跃会话的品种集合」为作用面**（等价于复用 gate 的 `symbol:<品种>` 档）。被否决：那是**随会话启停漂移的实时交集**，漂移方向恰好是「窗口中间新起的会话不在集合里、从缝里穿过去」——漏拦在极端行情里就是敞口。

## Consequences

- **幂等键含账户而非会话**，所以「同一账户 × 同一事件 × 同一品种」无论有几个会话，都只减一次。
- **减仓结果通知的受众独立于窗口通知的裁剪规则**：窗口开启/结束两条按「作用域是否命中」裁剪（提醒可以裁掉噪声），而减仓通知按「该账户在该品种上有净持仓」判定——**只要减了你的仓，你必然收到那条通知，哪怕你当时没有任何活跃会话**。告知一次**已发生的不可逆动作**，不能裁。
- **「每个受影响品种各自减半」中的「品种」是账户持仓维度上的品种**，不是「每个会话的品种」。
- **撤单里「开仓挂单」的判定与它同维度**：「与当前账户持仓方向相反」；一只空仓账户上的买单**就是**开仓单。
- **账户是起点，不是组合**：这里说的「账户」指 `ExchangeAccount`（一个交易所 API 凭证 = 一个真实持仓所在），不是用户。同一用户绑多个账户时，每个账户各自判定、各自减半——它们本来就是互不相干的持仓。

## 补充（2026-10-06）：盈亏**归属** ≠ 减仓**目标**

本 ADR 定的是减仓的**目标**：作用对象是账户持仓，不是会话。它**不**回答「这笔减仓
实现的盈亏算谁的」——那是另一个问题，本次事故（「减仓成交从不落库」，见 CONTEXT.md
Resolved Decisions）把它逼了出来。

**盈亏归属采用「唯一活跃（账户 + 品种）会话，否则归空」**（`reduce_ledger.resolve_session_for`）：
恰好一条活跃会话才归给它，0 条或 >1 条一律 `None`（fail-closed，绝不硬挑一条）。归空的
盈亏计入账户口径，不进任何会话权益。

两件事不冲突的理由：减仓**目标**是账户持仓（因为持仓只存在于账户侧、会话会消失），而
盈亏**归属**是「谁下的单造成这笔敞口，盈亏就归谁」——会话自己的单本来就带
`live_session_id`，让手动/自动平仓也带上归属，口径才自洽。同账户同品种有多条活跃会话时
归空，是因为这时**挑谁都错**，而归空至少是诚实的。

配套改动：减仓成交当场落 `Order` 行（`persist_reduce_order`），历史缺口以交易所
`userTrades.realizedPnl` 为准回填（`reconcile_realized_pnl_from_exchange`）。
