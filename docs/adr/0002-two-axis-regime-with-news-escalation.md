# 行情阶段判定由「量化 + 资讯」两根轴构成，且资讯只能抬升

判定不是单一函数，而是两个输入：量化指标（ATR% 分位、EMA 斜率与间距、箱体、高低点结构）产出**基础阶段**，LLM 对当日资讯的判定产出**抬升标志**，**生效阶段** = 基础阶段被抬升后的值。资讯只能把阶段推向更保守方向——一律抬到「高波动」，不能放松、不能沿优先级挪一档。这条打破了两条原本更干净的设计（判定纯量化；LLM 只写解释文字），是权衡后的刻意选择。

## Considered Options

- **资讯只做日报里的解释文字，不进判定**（原推荐方案）。被用户推翻：原始需求就是「每天收集资讯，确定当前所处大的行情阶段」，把资讯降级成旁注等于取消了需求的一半。
- **资讯与量化写进同一个字段，按固定优先级取一个。** 被否决：归因会断。日报说「今日高波动」时，没有第二个数字能回答「是 ATR 分位超了，还是资讯把它抬上来的」——而「每条停用决策都要能回答依据什么」是硬要求。
- **资讯输出 0–100 的影响分，阈值化后并入优先级表。** 被否决：制造一个无人能解释的新数字（「影响分 73」）。
- **资讯沿优先级上移一档（箱体震荡 → 下行趋势）。** 被否决：抬升幅度取决于当时恰好处于哪个基础阶段，事后无法解释「为什么同样是利空，上周只降了一档」。资讯判定是一段不可复现的文本推理，它没有能力分辨「这条新闻值一档还是两档」——它的语义不是「判定阶段」，而是**声明进入风险状态**，而「高波动」正是为这个角色准备的档位。
- **双向影响（资讯也可以把高波动说成箱体震荡）。** 被否决：直接与「LLM 只能让系统更保守，永远不能让它更激进」冲突，等于把风控的松紧栓在一个不可审计、不可复现的输入上。

## Consequences

- **三个值（基础阶段 / 抬升标志 / 生效阶段）必须同时持久化**，Shadow 期的每日记录亦然。只留生效阶段会让「资讯改了几次口、改对没改对」在事后无法从数据里回答。
- **历史标签只能由量化算法产出**（资讯条目会消失，历史资讯不可重建），所以切片结论与实时判定**不是同一个函数**：切片回答的是「量化口径下的适用性」。这个不对称必须体现在验证里——成功标准①的一致率比对基准是纯量化口径，资讯抬升的日子单独统计，否则「资讯抬升判对了」的日子会被记成「判定与历史不一致」。**（现状 2026-09-26：两半都已落地。判据是**生效阶段与基础阶段不相等**——刻意不是「抬升标志非空」：基础阶段已是高波动时资讯照抬升、标志照记，但那天机制给出的就是纯量化答案，摘掉它等于把最极端的日子从分母里挑走。归属按**生效轴**（`effective_at <= 业务日界(那天)` 的最新一条），不是签署轴——抬升次日 08:00 才生效，按签署日归会差两天。那些天**排除出分母 + 单列一行**（另有 K = 其中人工标注与当天的生效阶段一致的天数，只让排除可审计，不参与达标判断）。四摊互斥：冲突 → 抬升 → 缺口 → 比对。见 `truth.py` 的模块 docstring。）**
- **资讯输入不可重放，可回放性只能由落库承担**：存下结论 + 引用的资讯条目（标题、链接、来源、发布时间、送进 LLM 的正文），不能靠「重跑一遍」。LLM 由此从「写解释」升格为**判定输入的生产者**。
- **抬升会撞上适用性门槛**：高波动恰恰是样本最稀有的阶段，多数策略在该格是「中性」，而「中性不构成停用理由」会让抬升什么都停不掉——资讯通道的全部动作量退化成日报里的一行字。因此高波动档不做适用性判断、对全体一律停开新仓（保命档）。
- **资讯抬升不受「最小持续期」约束**，但仍受「次日 08:00 生效」约束；按日生效，资讯撤下即解除，不需要人工确认。
- **保命档（高波动）作为候选阶段时同样不受持续期约束**（2026-11-16 补）：这条是上面那条的对称补丁，来源却是量化轴自己的失效——11-14 的 ATR% 分位已到 0.916、量化判 `high_vol`，落库仍 `range`，保命档被自己的防抖闸拦在门外 4 天。持续期的正当性建立在「早切晚切代价相当」这个对称假设上，而保命档管的是「此刻谁都不该开新仓」，方向上的不对称足以推翻它。**豁免单向**：只让系统更早进入风险状态，离开保命档照旧等满持续期；留痕走 `evidence["decision"]["dwell_exempt"]`，不复用 `reason`（`reason` 的语义是「为什么最后用的不是量化判出的那个」，豁免时用的正是它）。
- **最小持续期由 5 个自然日收到 3 个**（2026-11-16，`JUDGEMENT_LIFECYCLE.min_dwell_days`）：上面那次失效有两个成因，加豁免只解决了其中一个——那把闸本身也偏长。防抖要滤的是单日跳变，连续 3 天同一候选已足以排除噪声；多出来的两天不增加信息，只在行情拐头后继续按旧档位指挥停用。副作用是持续期现在短于 `ema_slope_lookback_days`（5 天），**刻意如此**：斜率回答「趋势有没有在走」，改口不必等确认趋势所需的同等观察量。已发出的历史记录不受影响（参数快照存在记录自己身上）。
