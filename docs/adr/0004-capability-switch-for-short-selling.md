# 双向持仓用能力开关引入，而不是直接把引擎改成双向

策略引擎原本是 **spot 单边语义**：`PortfolioTarget.target_quantity` 拒绝负数、
任何 `sell` 一律翻译成 `target_quantity=0`（目标空仓）、卖出量被
`min(qty, position)` 钳制。这套语义下 `halftrend_rsi` 这类双向策略**根本跑不起来**：
实测 20000 根 BTC/USDT 15m 上，策略原始发出 61 次 `entry_short` 信号，**成交 0 次**；
TP1 的「平 50%」被放大成「平 100%」（8/8 样本全部如此）；随后 `ctx.position`
与策略内部状态脱钩，策略在 bar#137 永久静默，之后 19863 根 bar 再没发过一笔订单。

我们要让引擎能表达空头与按量平仓。有两条路：**直接改成双向**，或者**加一个能力开关**。
我们选开关：`BaseStrategy.supports_short = False`（默认），只有显式声明 `True`
的策略才走双向分支。

## Considered Options

- **直接把引擎改成双向语义。** 被否决：当前有 20+ 个只做多策略与实盘会话在跑，
  而这条路径历史上出过两次**真实资金事故**——2026-09-20 把账户卖成 −17718 空头
  （按陈旧数量「平仓」，实际账户为 0），2026-09-27 BNB 双平（第二张平仓单开了空仓）。
  直接改语义意味着这些策略的下单行为在无人察觉的情况下改变，且没有回滚开关。
- **让每个策略自己实现 `construct_portfolio`。** 被否决：只解决「平 50%」，
  做空仍然要改 `_execute_sell` / `_position_value` / `_target_to_order`；
  而且每个策略各写一遍账务，等于把「穿越零点时怎么拆成交记录」这件事复制 N 份。
- **新增一张「持仓方向」表。** 被否决：净持仓是交易所侧的事实，本地表必然与它分叉，
  而按分叉的账面算出的平仓量在失真时会反向开仓——与 ADR 0003 否决「加本地持仓表」
  是同一个理由。

## Consequences

- **只做多策略逐位不变**，这是改造的硬约束，不是期望。已用真实引擎在 3000 根
  BTC/USDT 15m 上验证 `box_time_range_breakout_strategy`：改造前后 trades=17、
  收益 `-2.3859720068495136`、回撤 `-2.5372970941132547`、权益
  `9761.402799315048`，连 trades 与权益曲线的 SHA256 指纹都相同。
- **开关是注册期的闸门，不只是运行期的分派**。声明 `supports_short=True` 的策略
  默认**拒绝注册**并告警，需显式配置 `STRATEGY_ENGINE_ALLOW_SHORT` 才放行。
  理由：双向分支改的是实盘 `_target_to_order`，而该路径合入时**尚未经真实资金
  链路验证**（`SignalDispatcher → RiskGuard → 交易所`）。刻意不 `raise`——策略引擎
  起不来会连带停掉所有只做多策略的决策，故障面比「少注册一个策略」大得多。
- **回测侧必须补一层做空约束**。实盘 RiskGuard 3c 按
  `Σ|position_value × leverage| / equity ≤ 100%` 拦单，回测没有这层；若开空完全不设
  上限，回测会允许「实盘一定被拒」的仓位，且**系统性奖励做空**（多头受现金约束、
  做空不受）。用初始保证金口径堵住：开空要求
  `qty × price × short_margin_rate ≤ 可用现金`，默认 20%（5x），与适配器
  `DEFAULT_LEVERAGE` 对齐。**刻意不引入完整杠杆模型**（强平、维持保证金、资金费率
  叠加）：那会改变所有现有策略的回测数字，违反上面那条逐位不变的承诺。
- **`_position_value` 对空头必须返回负市值**。改造前对 `position <= 0` 短路返回 0，
  那是「不可能有空头」的假设；不改的话空头浮亏不进权益曲线，最大回撤与夏普失真。
- **买入侧的 `reduceOnly` 判定与卖出侧对称**。`diff > 0` 分支此前直接
  `return ctx.buy(...)`，从不设 `is_close_position`，于是「平掉空头」这张买单在交易所
  侧**不带 reduceOnly**——正是 2026-09-27 事故的镜像（那边平多超量变反向开空，
  这边平空超量变反向开多）。判定口径是「目标是否为空仓」：`target == 0` 带标志，
  `target > 0`（反手做多）不带，带了会被交易所拒单（-2022）。
- **启用做空的验收门槛不是单测通过**。必须先在测试网跑通「开空 → 部分平 → 回补 →
  反手」四步，并**故意构造平空超量**来验证 reduceOnly 真的拦住反向开多。
  只跑「能开能平」证明不了本次修的东西。
